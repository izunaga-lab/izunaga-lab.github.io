## 1. はじめに（手元での確認）

### 必要なもの

- **Hugo（extended 版）v0.156 以降**
  - 現在は v0.168.0 を使用しています．`hugo version` で確認できます．
  - 表示に `+extended` が含まれている必要があります．
  - Mac：`brew install hugo`（更新は `brew upgrade hugo`）
  - 古いバージョンでは `hugo.Data` や `locale` の部分でエラーになります．
- **Git**

### 手元で表示する

`hugo.toml` があるフォルダで次を実行します．

```bash
hugo server
```

表示されたアドレス（通常は http://localhost:1313/ ）をブラウザで開きます．ファイルを保存すると自動で再読み込みされます．終了するときは `Ctrl + C` を押します．

- 下書き（`draft: true`）の記事も表示したい場合は `hugo server -D` を使います．
- 「port 1313 already in use」と表示された場合は，前に起動した `hugo server` が動いたままです．[困ったときは](#9-困ったときは)を参照してください．

### 公開サイトに反映する

```bash
git status                    # 変更されたファイルを確認（意図しないファイルがないか）
git add .
git commit -m "変更内容のメモ"
git push
```

push 後，GitHub の Actions タブでビルドが緑のチェックになれば，数分で公開サイトに反映されます．

## 2. 公開の仕組み

- ワークフロー：`.github/workflows/hugo.yaml`
- GitHub の Settings → Pages → Source は「**GitHub Actions**」にしてあります．
- 次のタイミングで自動的にビルド・公開されます．
  - main ブランチへの push
  - **毎日 0:00（日本時間）の定期実行**
  - Actions タブからの手動実行（「Run workflow」）

毎日の定期実行は，トップページの「過去3か月のお知らせ」の判定や，未来の日付で書いたお知らせを日付どおりに表示するためのものです．

> **注意**：GitHub の仕様で，60日間 push のないリポジトリでは定期実行が自動で停止します．停止するとメールで通知が届くので，Actions タブから再度有効にしてください．

### Hugo のバージョンを上げるとき

手元の Hugo を更新したら，`.github/workflows/hugo.yaml` の `hugo-version` も同じバージョンに書き換えてください．手元と公開時のバージョンが違うと，「手元では表示できたのに公開するとエラーになる」原因になります．

## 3. ファイル構成

普段の更新で触るのは，主に `content/`（文章）と `data/`（一覧のデータ）です．

```
.
├── hugo.toml                      サイト全体の設定（研究室名・所属・メニューなど）
├── content/                       各ページの文章（Markdown）
│   ├── _index.md                  トップページの紹介文
│   ├── about/                     研究室紹介
│   │   ├── _index.md              　概要
│   │   ├── research.md            　研究内容
│   │   ├── careers.md             　進路状況（表は data/careers.yaml）
│   │   └── seminar.md             　ゼミ情報
│   ├── members/_index.md          メンバー（一覧は data/members.yaml）
│   ├── publications/_index.md     研究成果（一覧は data/publications.yaml）
│   ├── news/                      お知らせ（1件1フォルダ）
│   └── awards/                    お知らせにしない受賞の詳細ページ（1件1フォルダ）
├── data/                          一覧のデータ（YAML）
│   ├── members.yaml               メンバー
│   ├── publications.yaml          研究成果
│   └── careers.yaml               進路状況
├── archetypes/                    hugo new content で作るときのひな形
│   ├── default.md
│   ├── news.md
│   └── awards.md
├── assets/css/style.css           デザイン（色・フォント・大きさ）
├── layouts/                       HTML テンプレート（普段は触らない）
│   ├── index.html                 トップページ
│   ├── _default/                  共通のページ（記事・一覧）
│   ├── about/                     研究室紹介のページ
│   ├── members/list.html          メンバーのページ
│   ├── publications/list.html     研究成果のページ
│   ├── awards/single.html         受賞の詳細ページ
│   ├── partials/                  部品（ヘッダー，フッター，所属表示，背景写真など）
│   └── shortcodes/careers.html    進路状況の表
├── static/                        そのまま公開するファイル（favicon など）
└── .github/workflows/hugo.yaml    自動公開の設定
```

`public/` と `resources/` はビルドのたびに自動で作られるフォルダです．Git の管理対象外（`.gitignore`）で，削除しても問題ありません．

## 4. サイト全体の設定

`hugo.toml` の `[params]` で設定します．

| 項目 | 内容 | 表示される場所 |
| --- | --- | --- |
| `labName` | 研究室名 | ヘッダー，トップページ，フッター |
| `labNameEn` | 研究室の英語名 | トップページ |
| `university` | 大学名（不要なら行ごと削除） | トップページ，フッター |
| `affiliation` | 所属（複数可．「 / 」区切りで表示） | トップページ，フッター |
| `description` | サイトの説明 | 検索結果などに表示される説明文 |
| `address` | 住所 | フッター |
| `email` | メールアドレス | ゼミ情報のページで `param "email"` を使っている場合のみ |
| `heroMax` | トップの背景写真の最大枚数（省略時は6） | トップページ |

所属は次のように複数書けます．1つだけの場合は `affiliation = "経済学部 経済工学科"` でも構いません．

```toml
  university = "〇〇大学"
  affiliation = [
    "大学院経済学府 経済工学専攻",
    "経済学部 経済工学科",
  ]
```

そのほかの設定：

- `timeZone = "Asia/Tokyo"`：日付を日本時間として扱う設定です．削除しないでください（削除すると，当日の朝9時より前に書いたお知らせが表示されなくなります）．
- `[markup.goldmark.extensions.cjk]`：日本語の文章の改行で余計な空白が入らないようにする設定です．
- `[[menus.main]]`：メインメニューの項目です．`weight` の小さい順に並びます．

> `email` の行は，ゼミ情報のページ（`content/about/seminar.md`）で `param "email"` を使っている間は削除しないでください．ビルドがエラーになります．

## 5. ページごとの更新方法

### 5.1 トップページ

| 変えたいもの | 編集する場所 |
| --- | --- |
| 紹介文 | `content/_index.md` の本文 |
| 研究室名・所属 | `hugo.toml` の `[params]` |
| お知らせの表示期間・件数 | `layouts/index.html` の `$months`（期間・月数）と `$maxItems`（最大件数） |
| 背景の写真 | 各記事の `hero:`（[6.3 トップページの背景写真](#63-トップページの背景写真)） |
| 「研究室を知る」のリンク | 各ページの `title:` と `description:` |

トップページのお知らせ欄には，**過去3か月以内**のお知らせが新しい順に最大10件表示されます．該当するお知らせがない期間は「過去3か月のお知らせはありません．」と表示されます．

### 5.2 お知らせ（`content/news/`）

**新しいお知らせを作る**

```bash
hugo new content news/2026-11-15-conference/index.md
```

フォルダ名は「日付-内容を表す英単語」の形にしておくと管理しやすくなります．フォルダ名がそのまま URL になります（例：`/news/2026-11-15-conference/`）．日本語やスペースも使えますが，URL が読みにくくなるので半角英数字とハイフンがおすすめです．

**記事の書き方**

```markdown
---
title: "研究室見学会を開催します"
date: 2026-11-15
draft: false
hero: photo.jpg
---

ここに本文を書きます．
```

| 項目 | 内容 |
| --- | --- |
| `title` | タイトル．トップページ・お知らせ一覧・記事上部に表示されます |
| `date` | 日付．並び順はこの日付で決まります（フォルダ名ではありません） |
| `draft` | `true` にすると下書き（公開されません） |
| `hero` | トップページの背景に使う写真（任意） |

**表示されないときの確認ポイント**

- `draft: true` になっていないか
- 日付が未来になっていないか（未来の日付の記事は，その日の0時の定期ビルド後に表示されます）
- 同じ日付の記事の順番を指定したい場合は，`date: 2026-11-15T15:00:00` のように時刻まで書きます

**リンク**

```markdown
詳細は[学会のウェブサイト](https://example.org/)をご覧ください．
受賞の一覧は[研究成果](/publications/)に掲載しています．
```

サイト内のページは `/` から始まるパスで書けます．

### 5.3 研究室紹介（`content/about/`）

| ページ | ファイル |
| --- | --- |
| 概要 | `content/about/_index.md` |
| 研究内容 | `content/about/research.md` |
| 進路状況の説明文 | `content/about/careers.md`（表は [5.6](#56-進路状況datacareersyaml)） |
| ゼミ情報 | `content/about/seminar.md` |

ページの並び順は各ファイルの `weight:` で決まります．タブの名前は `title:`，トップページの「研究室を知る」の説明文は `description:` です．

**研究内容**：「オペレーションズ・リサーチと数理最適化」の概要と，研究テーマ（ロバスト最適化，逆最適化）の紹介で構成しています．

**ゼミ情報**：定例ゼミの表，現在のゼミ（3年生ゼミ・院生ゼミと使用テキスト），過去に院生ゼミで使用したテキストで構成しています．年度が替わったら，院生ゼミの輪読テキストを「過去に院生ゼミで使用したテキスト」の一番上に移してください．テキストの表記は次の形で揃えています．

```markdown
- 〇〇 〇〇（20XX）『〇〇入門』〇〇出版．
- Author, A. (20XX). *Title of the Book*. Publisher.
```

### 5.4 メンバー（`data/members.yaml`）

```yaml
faculty:                                  # 教員
  - name: 伊豆永 〇〇
    name_en: 〇〇 Izunaga
    position: 〇〇
    research: 数理最適化，オペレーションズ・リサーチ   # 「専門」として表示
    email: xxx [at] example.ac.jp                    # 不要なら行ごと削除
    links:                                          # 不要なら行ごと削除
      - label: researchmap
        url: https://researchmap.jp/

students:                                 # 在籍学生（group ごとに表を作成）
  - group: 修士課程
    members:
      - { grade: M1, name: 〇〇 〇〇, affiliation: 大学院経済学府 経済工学専攻 }
  - group: 学部4年
    members:
      - { grade: B4, name: 〇〇 〇〇, affiliation: 経済学部 経済工学科 }

alumni:                                   # 卒業生・修了生（新しい年度を上に）
  - year: 2025年度
    members:
      - 〇〇 〇〇（修士）
```

- `group` は書いた順に表示されます．学部3年生の配属が決まったら `- group: 学部3年` を追加します．
- 表の「所属」の列には `affiliation` の内容が表示されます．

### 5.5 研究成果（`data/publications.yaml`）

`items` に1件ずつ追加します．**書く位置はどこでも構いません**（並び順は自動で決まります）．

```yaml
  - type: domestic                 # 区分（下の表を参照）
    date: 2026-09-12               # 発表日・受賞日（新しい順に並ぶ．年も自動で決まる）
    refereed: true                 # 査読あり（任意）
    authors: [佐藤 花子, 伊豆永 〇〇]
    presenter: 佐藤 花子            # 発表者（任意．下線が付く）
    title: 〇〇を用いた〇〇の推定
    venue: 〇〇学会 第〇回全国大会
    detail: 2B-04                  # 巻号・ページ・会場など（任意）
    doi: 10.0000/xxxx              # 任意
    url: https://...               # 任意
    note: 学生奨励賞                # 強調表示されるメモ（任意）
    news: /news/2026-09-12-award   # お知らせ記事へのリンク（任意）
    news_label: 賞状・受賞のお知らせ
```

**区分（`type`）**

| `type` | 表示名 |
| --- | --- |
| `journal` | 学術論文（査読あり・なしをまとめて記載） |
| `international` | 国際会議 |
| `domestic` | 国内学会・研究会 |
| `award` | 受賞 |

区分の名前や順番は，ファイル先頭の `categories` で変更できます．

**主な項目の説明**

| 項目 | 内容 |
| --- | --- |
| `date` | 発表・受賞の日付．新しい順に並び，年の見出しも自動で決まります．`date` を書けば `year` は不要です |
| `year` | 日付がないもの（論文など）．同じ年の中は書いた順に並びます |
| `refereed: true` | タイトルの上に「査読あり」のタグが付き，見出しに「（うち査読あり〇件）」と表示されます |
| `presenter` | `authors` の中のこの名前に下線が付きます．**`authors` と一字一句同じ表記**にしてください |
| `news` / `news_label` | お知らせ記事へのリンク．`news_label` を省略すると「お知らせ記事」と表示 |
| `more` / `more_label` | 受賞の詳細ページ（`content/awards/`）へのリンク．`more_label` を省略すると「詳細」と表示 |

> `detail` は巻号・ページ数の欄です．詳細ページへのリンクには `more` を使ってください．

**ビルド時の警告**：次の場合はターミナルに警告が表示されます．

- `date` も `year` もない
- `presenter` が `authors` の中に見つからない
- `news` や `more` のリンク先のページが見つからない（下書きの場合も含む）

### 5.6 進路状況（`data/careers.yaml`）

```yaml
period: 2021〜2025年度                    # 対象期間（不要なら行ごと削除）

graduate:                                 # 大学院修了者
  - { name: 〇〇株式会社, yomi: まるまる }
  - 〇〇株式会社                           # 同じ進路の2行目以降は名前だけでOK
  - { name: 本学 博士後期課程 進学, yomi: ほんがくはかせこうきかてい }

bachelor:                                 # 学部卒業者
  - { name: 本学大学院 進学, count: 5, yomi: ほんがくだいがくいん }
```

- **1人につき1行**書きます．年度が違っても同じ進路はそのまま重ねて書けば，自動で合算されます．
- 人数が多い進路は `count` でまとめて書けます．
- 人数は **2名以上の進路だけ**表示されます．各区分の見出しには合計人数が表示されます．
- 並び順は，**名前に「進学」を含む進路が先**，それ以外が後で，それぞれ**五十音順**です．
- 五十音順に並べるため，各進路に**読み（`yomi`）**を書きます．同じ進路が複数あるときはどれか1行にあれば十分です．ひらがな・カタカナどちらでも構いません．「株式会社」は読みに含めません．`yomi` がない進路は，ビルド時に警告が表示されます．
- 表記（括弧の全角・半角，スペースなど）が違うと別の進路として数えられます．既存の行をコピーして使ってください．

> **個人情報への配慮**：年度は表示していません（卒業生一覧と組み合わせて個人が特定されるのを防ぐため）．「1名」の進路は特定の手がかりになりやすいので，対象期間を長めにする，業種でまとめるなどで調整してください．掲載する進路は本人の了解を得てください．

### 5.7 受賞の詳細ページ（`content/awards/`）

数年前の受賞など，**お知らせには載せずに**賞状などの詳細を掲載したいときに使います．ここに置いたページは，トップページやお知らせ一覧には表示されず，研究成果の受賞欄からのリンクでだけたどれます．

```bash
hugo new content awards/2022-11-award/index.md
```

```
content/awards/2022-11-award/
├── index.md
└── certificate.jpg
```

研究成果の側では `more:` でリンクします．

```yaml
  - type: award
    date: 2022-11-20
    authors: [〇〇 〇〇]
    title: 優秀発表賞
    venue: 〇〇学会 20XX年度秋季研究発表会
    more: /awards/2022-11-award
    more_label: 賞状
```

> `content/awards/_index.md` は一覧ページを作らないための設定ファイルです．削除しないでください．

## 6. 写真・画像の扱い

### 6.1 記事に画像を載せる

画像は記事と同じフォルダに置きます（記事はフォルダ形式にし，ファイル名は必ず `index.md`）．

```markdown
![学会会場で発表する佐藤さん](photo.jpg)
```

キャプションを付ける場合は `figure` を使います．

```markdown
{{< figure src="photo.jpg" alt="学会会場で発表する佐藤さん" caption="〇〇学会での発表の様子" >}}
```

賞状など縦長の画像は `width="480"` を付けると表示幅を抑えられます．

```markdown
{{< figure src="certificate.jpg" alt="学生奨励賞の賞状" caption="〇〇学会 学生奨励賞 賞状" width="480" >}}
```

- `alt` は画像の説明文です（読み上げソフトなどで使われます）．空にせず，何が写っているかを書いてください．
- `{{<` と `>}}` の間に `/*` `*/` を入れると，画像ではなく文字として表示されてしまうので注意してください．

### 6.2 PDF の賞状

`figure` では PDF は表示できません．画像に変換して表示します．

- Mac のプレビューで PDF を開き，「ファイル」→「書き出す」→ フォーマット「JPEG」
- **解像度は 150 ピクセル/インチ**（A4 で約 1240×1750 ピクセル），品質は中央よりやや右
- B4 など大きい賞状は 120 ピクセル/インチ程度

原本の PDF も確認できるようにしたい場合は，同じフォルダに置いてリンクします．

```markdown
[賞状のPDFを開く](certificate.pdf)
```

### 6.3 トップページの背景写真

記事の先頭に `hero:` で写真のファイル名を書くと，トップページの研究室名の背景に表示されます（6秒ごとに切り替わり）．

```markdown
---
title: "研究室見学会を開催しました"
date: 2026-11-20
hero: photo.jpg
---
```

- 日付の新しい記事から順に，最大6枚（`hugo.toml` の `heroMax` で変更可）が使われます．
- 写真は自動で切り抜き・縮小・WebP 変換されます．**横長の写真**を選んでください．
- 記事はフォルダ形式にし，写真を同じフォルダに置く必要があります．
- `hero:` を指定した記事が1つもない場合は，白い背景のデザインで表示されます．
- 右下の「一時停止」ボタンで止められます．「視差効果を減らす」設定の環境では自動で切り替わりません．

### 6.4 画像を載せるときの注意

- **サイズ**：横幅 1600px 程度，1枚 500KB 以下を目安に縮小してから入れてください．
- **位置情報の削除**：スマートフォンの写真には撮影場所（GPS）が記録されていることがあります．Mac のプレビューでは「ツール」→「インスペクタ」から削除できます．
- **本人の了解**：人が写っている写真，氏名が記載された賞状は，掲載前に本人の了解を得てください．トップページの背景に使う場合は特に目立つため，背景に使ってよいかも確認してください．

## 7. デザインの変更

デザインは `assets/css/style.css` で管理しています．

### 色

ファイル先頭の `:root` にまとめています．`--accent` が藍色のアクセントカラーです．ダークモード用の色は，その下の `@media (prefers-color-scheme: dark)` の中にあります．

### フォント

| 用途 | フォント | 変更する場所 |
| --- | --- | --- |
| 本文 | BIZ UDPゴシック | `--font-body` |
| 見出し | Noto Sans JP | `--font-head` |

フォントを変えるときは，次の **2か所** を変更します．

1. `layouts/partials/head.html` の Google Fonts の読み込み（`family=...` の部分）
2. `assets/css/style.css` の `--font-head`（または `--font-body`）

見出しを本文と同じ BIZ UDPゴシックの太字にする場合は，`--font-head: var(--font-body);` とし，head.html から見出し用フォントの読み込みを外します．

### 文字の大きさ

| 対象 | CSS の場所 |
| --- | --- |
| トップページの研究室名 | `.hero-title` の `font-size` |
| トップページの「お知らせ」「研究室を知る」 | `.home-grid .section-title` |
| 各ページの見出し（「教員」「学術論文」など） | `.section-title` |
| お知らせ・受賞の記事ページのタイトル | `.page-header.is-post h1` |
| その他のページのタイトル | `.page-header h1` |

`font-size: clamp(最小, 画面幅に応じた値, 最大)` の形になっているものは，パソコンでは主に3つ目の「最大」の値が使われます．

### 変更前の内容をコメントで残す

- テンプレート（`.html`）：`{{/* ここにコメント */}}`（`{{` と `/*` の間にスペースを入れない）
- CSS：`/* ここにコメント */`

Git で管理しているので，過去の状態は GitHub のファイル画面の「History」からも確認できます．

## 9. 困ったときは

### 「port 1313 already in use」と表示される

前に起動した `hugo server` が動いたままです．別のアドレス（例：http://localhost:52999/ ）で起動しているので，いつもの 1313 番を開くと古い画面が表示されます．次のコマンドでまとめて止めてから，改めて `hugo server` を実行してください．

```bash
pkill hugo
```

### 変更が反映されない・リンク先が古いまま

1. `hugo server` を `Ctrl + C` で止めて，もう一度起動する（動かしたままファイルやフォルダを移動すると，正しく反映されないことがあります）
2. それでも直らない場合は，`public` と `resources` のフォルダを削除してから `hugo server` を実行する
3. Hugo が認識しているページと URL を確認する

```bash
hugo list all
```

4. 記事の先頭に `slug:` や `url:` が紛れ込んでいないか確認する
5. 古いファイル（例：`2026-09-11.md` と `2026-09-11-award/` の両方）が残っていないか確認する

### 記事やリンクが表示されない

- 記事の `draft: true` を削除したか（`hugo new content` で作ると自動で入る場合があります）
- フォルダ内のファイル名が `index.md` になっているか（`_index.md` や `index.md.txt` ではないか）
- ターミナルに `WARN` で始まる警告が出ていないか

### テンプレートを差し替えたのに反映されない

Hugo は決まったファイル名しか読み込みません．差し替え用のファイルを受け取ったときは，名前と置き場所を確認してください．

```bash
ls layouts/publications/ layouts/awards/
```

例：`publications-list.html` → `layouts/publications/list.html`，`awards-single.html` → `layouts/awards/single.html`

### YAML でエラーになる

- 字下げは**スペース**で揃える（タブ文字は使えない）
- 同じ項目の中の行は，同じ字下げにする
- 値に半角の `: `（コロンとスペース）を含む場合は `"` で囲む
- エラーメッセージに行番号が表示されるので，その行の前後を確認する

### 公開サイトだけ表示がおかしい

- Actions タブで最新のビルドが緑のチェックになっているか
- ブラウザの強制再読み込み（Mac：`Command + Shift + R`）
- GitHub のリポジトリ画面で，不要なファイルが残っていないか

### 「pages build and deployment」が赤い×になっている

Settings → Pages → Source が「Deploy from a branch」になっていたときに自動で実行される別の仕組みです．Source が「GitHub Actions」になっていれば，今後は実行されません．過去の失敗は無視して構いません．
